# 书库 Shuku

装在 NAS 上的电子书和漫画书库：把书拖进去，自动识别书名作者、按规范改名归类；电脑和 iPhone 用网页读，安卓手机和 Wear OS 手表用客户端，进度在各设备之间同步。在家走内网，出门自动切到 Tailscale。浏览器插件能把任何网站上的电子书一键加入书库。

当前进度：

- 第一阶段（NAS 服务端 + 网页端）、第二阶段（联网补全、书内搜索、听书、阅读统计、OPDS）：已完成。
- 第三阶段（安卓 App、Wear OS 手表 App、浏览器插件、“发现”页）：已完成。NAS 服务器镜像发在 ghcr.io（Container Station 自己下载、自动升级）；安卓 App、手表 App、浏览器插件和 compose 文件在仓库的 Releases 里，装好书库后也能直接从书库网页下载。安装见[部署到威联通](#部署到威联通)。
- 在线升级：各端都能发现新版本并升级，见[在线升级](#在线升级)。
- 1.0.0.7：家人账号、划线笔记、系列、批量管理、回收站、自动备份、离线读书（网页）等，见[家人账号](#家人账号)、[备份和恢复](#备份和恢复)、[出问题时](#出问题时)。

## 现在能做什么

- **入库**：网页里拖拽文件或整个文件夹，或者直接丢进 NAS 的投递文件夹。自动去掉网站水印、“精校版”等后缀，读取书里的内嵌信息，可选用 AI 恢复正式书名。识别把握大的直接按命名规则归档，把握不大的进“待确认”。
- **整理建议**：相似文件夹（“刘慈欣”和“刘 慈欣”）、同一作者的不同写法（含拼音/英文名）、散落的系列、同一本书登记多次、重复文件、没按规则命名的书、空文件夹。每条都能预览、一键执行、整批撤销。所有移动都有记录，**不会删除任何文件**（删除书会移到书库的 `_回收站`）。
- **阅读**：
  - EPUB、MOBI、AZW3、FB2：字体、字号、行距、段距、页边距、首行缩进、两端对齐；左右翻页或上下滚动，宽屏自动双栏；目录、书签、书内搜索。
  - TXT：自动识别 GBK/GB18030/Big5/UTF-8 编码，按“第X章”智能分章。整本没有换行、一章挤在一行里的 TXT 也会按段落和句子切开，几千章的长篇网文在手机上也是一两秒打开。
  - PDF：按需分段下载（大文件不用等），连续滚动或单页翻页，缩放，目录。
  - 翻页：点屏幕左边三分之一往前翻，正中间叫出工具栏，其余地方往后翻；轻轻一划也翻一页。
  - 自动翻页：照你平时的阅读速度自动翻页（字多的页停久一点），平时自己翻页时就在学，嫌快嫌慢都会跟着改。
  - 漫画（CBZ/CBR/CB7/CBT/ZIP/RAR）：单页、双页（自动识别跨页大图）、条漫；日漫从右到左；内网看原图，Tailscale 下按屏幕压缩。
  - DOCX、CHM、RTF 等冷门格式：用 Calibre 转成 EPUB 再读（发布的镜像里已经带了）。DJVU 转 PDF 再读。
  - 划线和笔记（四种颜色，PDF 也行），脚注弹窗、跳走后“返回原处”，繁体书转简体读，PDF 能选字、查字典、复制、搜索高亮，底栏显示本章和全书大约还要读多久，读完一卷提示下一卷。
  - 每本书单独记住阅读设置（翻页方式、漫画方向、缩放、繁转简），换设备也在。另一台设备读得更靠后时会提示跳过去。
  - 快速排版：底栏“字号”一点，小字 / 标准 / 大字三档（PDF 是缩小 / 适合 / 放大）。
  - 翻译本页：点“翻译”，这一页每段原文后面跟着译文（原文还在，划线、进度、听书照旧按原文），开着翻译接着翻页也会自动翻；PDF 打开原文、译文对照的面板。用微软翻译（免费，不用设置）或者自己配置的 AI，在“设置 → 翻译”里选，还有默认译成哪种语言（阅读时也能换）。翻过的段落存在书库里，再看不用重翻。
  - 扫描版 PDF、DJVU（每页都是图片）：翻到哪一页，书库就在 NAS 上识别那一页的文字（简体、繁体、英文、日文，tesseract），铺一层看不见的文字，能选字、复制、查字典、划线、搜索、听书、翻译。识别过的页存在缓存里。
- **笔记**：所有划线和笔记集中在“笔记”页，按书分组，能搜索、编辑，导出 Markdown。
- **离线读书（网页）**：用 https 地址（比如 Tailscale 的 `https://nasfinecycle.tailbb4459.ts.net`）打开书库时，书的详情里点“离线可读”，书存在浏览器里；断网时在“离线书架”里照样能读 EPUB、PDF、漫画，进度联网后自动同步。iPhone 上请先“添加到主屏幕”再存书（不然 Safari 7 天没打开会清掉存的书）。安卓 App 用“下载到手机”。
- **夜间模式**：六套阅读主题（白、纸、绿、灰、纯黑、暖夜），夜间模式可以跟随系统或按时间自动切换，单独选择夜间主题；软件亮度（可以低于系统最低亮度）、暖色滤镜；PDF 夜间反色。界面在页面绘制前就确定深浅色，夜里打开不会闪白。
- **搜索**：书名、作者、系列、标签，支持全拼、首字母（输入 `st` 找到《三体》）、繁简互搜。
- **选词查字典**：阅读时选中不认识的字词（手机上长按），弹出读音和释义：中文用教育部《重编国语辞典修订本》的释义加大陆拼音（和台湾读音不同的会标出来），英文用 ECDICT 的音标、中文释义，还能认出 went、running 这样的变形。点喇叭听发音（按语言挑微软自然语音，中、英、日、韩、泰、法、德等都能读）。点“AI 解释”让 AI 结合这句话的上下文解释，任何语言都行，选一整句外文就是翻译。本地字典打在镜像里，断网也能查（AI 和发音要联网）。阅读设置里可以关掉。
- **听书**：阅读器里点耳机图标（或按 `R`）开始朗读，高亮当前句子、自动翻页；语速、音色随时换；睡眠定时（15 / 30 / 60 分钟或读完本章）；手机锁屏也能暂停、切句。声音来源三选一：
  - 微软自然语音（默认，免费，和 Edge 浏览器“大声朗读”同一套：晓晓、晓伊、云希、云健、云扬、粤语、台湾腔等）。NAS 需要能访问 `speech.platform.bing.com`。
  - 任何 OpenAI 兼容的语音接口：OpenAI、硅基流动，或 NAS 上的 Kokoro、openai-edge-tts 等本地服务。
  - 设备自带语音：前两种用不了时自动切换，断网也能读。
  - 每台设备可以自己选“在线合成”还是“本机语音”：阅读设置的“听书”里就能换（网页、手机 App、手表都有）。
  - 外文书：按书的语言自动选声音（英、泰、日、韩、法、德、西、俄、越……），每种语言记住选过的声音；书里夹着别的文字时自动换成能读的声音。
  - 安卓 App 关屏听书：网页被系统冻结或回收时，App 直接从书库取后面的章节接着读。
  - **听书播放器**（书的详情页“听书”，或阅读页听书菜单里的“听书播放器”）：音乐播放器那样的界面，不受翻页影响。NAS 把全书按句切成“听书稿”，在后台合成“听书包”（1 倍速 MP3，语速由设备调）：网络好用微软，不行交给开着的 Windows 桌面版，再不行用 NAS 本地语音。开始听就至少准备 30 分钟，手机 App 把语音下载存到手机上（最多 1GB）再放，熄屏、断网一会儿都不卡。NAS 上最多 5GB，读完的书自动清掉。
  合成过的段落缓存在 NAS 上（默认最多 400MB），换设备接着听不用重新合成。
- **书内搜索**：给正文建索引，书架搜索框输入两个字以上，就列出哪本书的哪一章提到过，点一下直接跳到原文。支持 EPUB、TXT、MOBI、AZW3、FB2、PDF（有文字层的）；繁体简体互搜。
- **联网补全**：从豆瓣读书、Open Library、Google Books、Bangumi（漫画）查封面、简介、年份、ISBN、出版社。入库时自动核对书名作者，对得上就直接归档；详情页“联网查找”列出候选，挑一个填进去；“设置 → 联网补全”可以一键补全已有的书。只补空着的信息，不覆盖你改过的内容。NAS 连不上外网时自动暂停，不拖慢入库。
- **阅读统计**：今天、本周读了多久，连续阅读天数，今年读完几本，近 30 天每天的时长，读得最多的书。多设备一起算。
- **OPDS**：KOReader、静读天下、Librera、Panels、Yomu 等阅读器添加 `http://192.168.31.200:27200/opds`（用户名填你在书库里的名字，只有一个人时随意；密码是你的书库密码），就能浏览、搜索、下载书库里的书。家人用自己的名字和密码，只看得到允许他看的书库。
- **内外网自动切换**：填好内网地址和 Tailscale 地址后，打开时同时探测，内网通走内网，不通走 Tailscale；切换网络、请求失败时自动重新选择。网页、安卓 App、手表、浏览器插件都是这样。
- **发现**：在“发现”页浏览、搜索公开书库，一键加入书库：维基文库（中文古籍、近代作品，整部作品生成 EPUB）、古腾堡计划、互联网档案馆（可以直接下载的书）、Standard Ebooks。还能添加任何 OPDS 书源（Calibre-Web、COPS、Kavita 等，支持用户名密码）。
- **从链接添加**：书架页“添加”里粘贴下载链接，书库在 NAS 上直接下载入库（最多同时 3 个，单个最大 4GB）。链接打开的是网页时会说明原因。需要登录才能下载的网站，用浏览器插件。
- **设备**：“设置 → 手机、手表和浏览器插件”里生成配对二维码和配对码（10 分钟内有效，只能用一次），给安卓 App、手表、浏览器插件登录用；所有登录过的设备都列在这里，可以单独移除。
- **回收站**：删除的书移到每个书库目录下的 `_回收站`，30 天内能在“设置 → 回收站”里恢复（书目、每个人的进度和笔记一起回来），30 天后自动彻底删除，也可以一键清空。
- **找不到的文件**：在 File Station 里改了名、挪了位置的书，扫描时自动接回原来的书目（进度、笔记都在）；文件真不见了先标成“文件找不到”，30 天内找回来自动恢复。共享文件夹没挂上（书库目录不在或者是空的）时不会动任何登记。
- **家人账号**：每个人用自己的名字和密码登录，进度、书签笔记、阅读统计、读完状态、评分、想读都分开；管理员管书和设置，家人只读，可以限定只看某几个书库。见[家人账号](#家人账号)。
- **自动备份**：每天备份一次数据库（进度、笔记、设置、书目），升级前也先备份；“设置 → 备份”里能下载、恢复。见[备份和恢复](#备份和恢复)。
- **存储与状态**：“设置 → 存储与状态”显示各种缓存占用（统一有上限，默认 5GB，超过先删最久没用的）、剩余空间、书库目录在不在、最近的错误和更新服务的状态，能一键清理缓存。
- **在线升级**：NAS 上的书库发布新版本后一分钟内自动换上；手机 App、手表 App、浏览器插件从书库检查新版本，提示更新。

## 部署到威联通

NAS 服务器的镜像发在 `ghcr.io/smallyjh-boop/shuku`（私有），Container Station 创建应用程序时自己下载，之后自动升级。NAS 已经用泰好说、记忆训练营那个 GitHub 只读令牌登录过 ghcr.io，不用再登录。

其他安装文件在 GitHub 仓库的 **Releases** 里（仓库页面右边栏“Releases”，或者 `https://github.com/smallyjh-boop/shuku/releases`，要先登录 GitHub）。最新的一个里有：

| 文件 | 装在哪 |
| --- | --- |
| `shuku-compose.yml` | 在 Container Station 里创建应用程序时粘贴的内容（和仓库里的 `docker-compose.yml` 一样） |
| `shuku-android.apk` | 安卓手机 |
| `shuku-wear.apk` | Wear OS 手表 |
| `shuku-extension.zip` | 电脑上的 Chrome / Edge |

装好书库以后，手机 App、手表 App、浏览器插件也可以直接在书库网页“设置 → 版本与升级”里下载，不用登录 GitHub。

**网络**：和 NAS 上其他程序（流水账房、极速 GTD、泰好说等）一样用宿主机网络（`network_mode: host`），书库直接监听 NAS 的 **27200** 端口，不经过 Docker 的端口转发——威联通上 Docker 的端口转发不通，用桥接网络加端口映射的容器访问不到、也上不了网（AI 识别、联网补全、听书、发现页都要上网）。NAS 上已经占用的端口：8080（QTS）、8720 / 8721 / 8730 / 8741（泰好说和它的更新服务）、8780 / 8781（极速 GTD）、8790（3D 运营管理系统）、8791（运营分析系统）、18765（3D 选品工具）、27180 / 27190（流水账房个人版 / 公司版）。

### 1. 准备文件夹

1. 控制台 → 权限 → 共享文件夹 →“创建”一个共享文件夹 `books`（小写，NAS 上的路径区分大小写，要和 `shuku-compose.yml` 里写的一样）。**一定要先建成共享文件夹**，否则数据会写进系统分区。
2. 在 File Station 里，`books` 下面建三个文件夹：`投递`、`图书`、`漫画`；`Container` 下面建一个 `shuku`。

| NAS 上的文件夹 | 用途 |
| --- | --- |
| `/share/books/投递` | 投递目录，丢进来的书自动入库 |
| `/share/books/图书` | 整理好的电子书 |
| `/share/books/漫画` | 整理好的漫画 |
| `/share/Container/shuku` | 数据库、封面、缓存 |

已经有书的话，直接把现有的书库文件夹挂载成 `/books`，启动后会原地登记，不会移动；之后可以在“整理”里一键按规范整理（可撤销）。

### 2. 创建应用程序

1. Container Station →**应用程序**→**创建**（旧版 Container Station 是“创建”→“创建应用程序”），应用程序名称填 `shuku`，把 `shuku-compose.yml`（或仓库里的 `docker-compose.yml`）的全部内容粘贴进去，点“验证 YAML”，再点“创建”。Container Station 会从 ghcr.io 下载镜像（带 Calibre，第一次大约三四百 MB），稍等一会儿。共享文件夹不叫 `books` 的，改 `volumes` 里冒号**左边**的路径（大小写也要一样）。
2. 浏览器打开 `http://192.168.31.200:27200`，设置管理员的名字和密码，就能用了。家人账号在“设置 → 家人账号”里加。

`shuku-compose.yml` 里已经填好了内网地址 `http://192.168.31.200:27200` 和 Tailscale 地址 `http://100.81.34.58:27200`，手机、手表、插件连上后自动在两者之间切换。27200 被占用的话，把 `SHUKU_PORT` 和这两个地址里的端口一起改。

**以前用导入的镜像装过**（`localhost/shuku`）：在“应用程序”里 shuku 的菜单点“编辑”，把内容换成新的 `shuku-compose.yml`，点“更新”（没有“编辑”的话，删除 shuku 再用新内容创建一次）。改动只有三处：`image` 换成 `ghcr.io/smallyjh-boop/shuku:latest`，加上 `labels` 那两行，加上 `SHUKU_UPDATE_URL`、`SHUKU_UPDATE_TOKEN` 两行。书、数据库、设置都在 `/share/Container/shuku` 和书库文件夹里，不会丢。换好以后，“映像”里旧的 `localhost/shuku` 可以删掉。

**升级**：不用管，见下面的[在线升级](#在线升级)。

**自己从源码构建**（一般用不到，比如 ARM 处理器的 NAS：发布的镜像只有 x86 版）：把整个仓库复制到 NAS，SSH 进去执行 `docker build -t localhost/shuku:latest .`，把 compose 里的 `image` 改成 `localhost/shuku:latest`、删掉 `labels` 那两行（否则更新服务会换回发布的版本），再创建应用程序。默认带 Calibre（镜像大约大 600MB），不需要转换 DOCX、CHM、RTF 等冷门格式的话，构建时加 `--build-arg FULL=0`。自己构建的镜像里没有手机、手表 App 和插件的安装包，也没有本地字典（查字典时只能用 AI 解释）。

### 3. Tailscale（出门访问）

NAS 上已经装好 Tailscale（Tailscale 地址 `100.81.34.58`），书库用宿主机网络，Tailscale 地址直接就能访问，不用另外设置：手机、电脑装上 Tailscale、登录同一个账号，在外面打开 `http://100.81.34.58:27200` 就行。安卓 App、手表和浏览器插件会自动在内网和 Tailscale 之间切换。

**可选：https**（iPhone 上想要书库离线缓存、安装成 App 时更完整）。SSH 登录 NAS（出现菜单按 `Q` 再按 `Y` 进入命令行），执行一次（NAS 上的 Tailscale 版本较旧，用老写法；443 被别的程序用了就换成 `https:10000`）：

```sh
/share/CACHEDEV1_DATA/.qpkg/Tailscale/tailscale serve https:443 / http://127.0.0.1:27200
# 新版 Tailscale 的写法：tailscale serve --bg --https=443 http://127.0.0.1:27200
```

之后用 `https://nasfinecycle.tailbb4459.ts.net` 打开，并在书库“设置 → 网络”里把 Tailscale 地址改成它。（需要先在 Tailscale 管理后台的 DNS 页面打开 MagicDNS 和 HTTPS Certificates，泰好说已经开过。）

**说明**：浏览器不允许 https 页面去请求 http 地址。所以 iPhone 上用 https 的 Tailscale 地址打开时，会一直走 Tailscale——在家时 Tailscale 会自动走局域网直连，速度不受影响。电脑用 http 内网地址打开时，两条线路之间可以自动切换。安卓 App、手表和浏览器插件不受这个限制，都能自动切换。

### 4. AI 识别（可选，强烈建议）

“设置 → 识别与整理”里选服务商、填 API Key，点“用示例测试”看效果。支持任何 OpenAI 兼容接口：DeepSeek、通义千问、Kimi、智谱、OpenAI，或 NAS 上的 Ollama。只会发送文件名、内嵌信息和开头几百字，不上传整本书。不配置时也能用，只是乱名文件更多会进“待确认”。

## 在线升级

在 GitHub Actions 里打包一次（见[打包](#打包github-actions)），所有端都会拿到新版本。手机、手表 App 和插件的安装包和服务器打在同一个镜像里，各端从书库取新版本（`/api/clients`、`/dl/…`），不用登录 GitHub。版本号是“填的版本号.第几次打包”，比如 `1.0.0.12`，各端都按它判断新旧。

| 哪一端 | 怎么升级 |
| --- | --- |
| NAS 服务器和网页 | 镜像推到 ghcr.io 后，NAS 上已有的更新服务（泰好说装的 `taihaoshuo-updater`）每分钟检查一次，一分钟内自动换上，书和设置都不动。Debian 和 Calibre 这些几百 MB 的运行环境单独做成基础镜像，没改就不变，平时升级只下载几十 MB。网页“设置 → 版本与升级”里能看到版本，点“检查更新”立即检查。升级后开着的网页会提示“书库已升级”，点“刷新”就是新版。 |
| 安卓手机 App | 打开 App 时检查（最多 6 小时一次），有新版本会问要不要更新，点“更新”下载后按系统提示安装。第一次会跳到“允许安装应用”，给书库打开后回来再点一次“更新”。也可以在“设置 → 版本与升级”里点“更新”。下载到手机的书和设置都会保留。 |
| Wear OS 手表 App | 手表上的书库首页会提示有新版本。在手机书库 App 的“设置 → 版本与升级”点“更新手表”：安装包存到手机的“下载”文件夹，再选 Wear OS 工具箱（或其他能给手表装 APK 的 App）装到手表；列表里没有的话，打开工具箱从“下载”文件夹里选 `shuku-wear.apk`。也可以用电脑的 adb 装。 |
| 浏览器插件 | 每 6 小时检查一次，有新版本时工具栏图标上显示“新”。打开插件点“下载新版本”，解压后把文件覆盖到原来加载的插件文件夹里，再点“已覆盖，重新加载”。（Chrome 不会自动更新“加载已解压的扩展程序”装的插件，所以要手动覆盖一次。） |

一键升级用到 compose 里的 `SHUKU_UPDATE_URL`、`SHUKU_UPDATE_TOKEN`（更新服务的地址和令牌，和泰好说的一样）；没填时自动升级照样进行，只是网页上的“检查更新”不能立即检查。更新服务没在运行时，在 Container Station 里启动 `taihaoshuo-updater` 就行。

**数据库升级**：新版本第一次启动时会自动升级数据库，升级前先把数据库备份到 `/share/Container/shuku/backup/`（文件名带 `upgrade`），升级失败时书库不启动、数据库保持原样。1.0.0.7 把全文索引（书内搜索用）从数据库里搬到单独的 `fulltext.db`，升级后会在后台重建，书多的话书内搜索要过一阵子才全。

**退回旧版本**：新版本有问题时，可以先退回上一版（ghcr.io 上留着最近 10 个版本）：

1. Container Station →“应用程序”→ shuku 的菜单 →“编辑”，把 `image` 改成 `ghcr.io/smallyjh-boop/shuku:v1.0.0.6`（换成想退回的版本号，Releases 里能看到），点“更新”。固定版本号的镜像不会被更新服务换掉；以后想恢复自动升级，再改回 `:latest`。
2. 退回到数据库升级以前的版本（比如从 1.0.0.7 退回 1.0.0.6）时，还要换回升级前的数据库：先在 Container Station 里停止 shuku；File Station 打开 `/share/Container/shuku`，删掉 `shuku.db`、`shuku.db-wal`、`shuku.db-shm`，把 `backup` 里最新的 `shuku-日期-upgrade-v3.db` 复制出来、改名成 `shuku.db`；再启动。升级以后记的进度和笔记会回到升级前的样子。

## 家人账号

第一次打开书库时设置的是**管理员**（名字默认叫“管理员”，可以改）。以前版本升级上来的，原来的密码就是管理员的密码，原来的进度、笔记都归管理员，登录过的设备不用重新登录。

“设置 → 家人账号”里添加家人：填名字和密码（至少 4 位），选“家人”或“管理员”，可以勾选他能看哪几个书库（不勾就是全部）。

- **管理员**：管书和设置——入库、整理、改书目、删书、发现、备份、家人账号都是管理员的事。
- **家人**：能看书、听书、查字典、划线记笔记、看自己的阅读统计，标读完、评分、想读；看不到整理、发现、上传和管理设置。
- 每个人的进度、书签笔记、阅读统计、读完状态、评分、想读、按书记住的阅读设置都是分开的。同一台平板上换人用：“设置 → 账号 → 退出登录”，再选自己的名字登录。
- 手机、手表、浏览器插件：用谁的账号生成配对码，配上的设备就是谁的。OPDS 用自己的名字和密码。
- 登录页有不止一个人时会列出名字，点自己的名字再输密码。
- 删除家人账号会把他的进度、笔记一起删掉（删除前书库会自动备份一次数据库）。

**忘记密码**：家人的密码管理员在“设置 → 家人账号”里重设。管理员忘了密码：Container Station 里编辑 shuku，在 `environment` 里加一行 `- SHUKU_RESET_PASSWORD=新密码`（至少 6 位），点“更新”；书库重启后第一个管理员的密码就是它。登录以后**记得再把这一行删掉**、再“更新”一次。

## 备份和恢复

数据库（书目、每个人的进度和笔记、阅读统计、设置、登录的设备）每天自动备份一次，放在 `/share/Container/shuku/backup/`：每天的留 7 份，升级前的留 5 份，手动备份的留 5 份，恢复前的留 3 份。备份不包括书本身（书在 `books` 共享文件夹里，用 QNAP 自带的 HBS 等工具备份）、封面和全文索引（能重新生成）。

“设置 → 备份”里能看所有备份、立即备份、下载到电脑、从某个备份恢复，或者上传以前下载的备份文件恢复。恢复时书库会先检查备份文件是否完整，把现在的数据库另存一份（“恢复前”），然后自动重启换上，大约十几秒。

另外，删除书库目录、删除家人账号之前也会自动备份一次。

## 出问题时

- **看日志**：Container Station →“容器”→ shuku →“日志”。“设置 → 存储与状态”里有最近的错误和警告、各书库目录在不在、剩余空间、更新服务的状态。
- **升级没生效**：“设置 → 版本与升级”看当前版本，点“检查更新”。提示没有换新版本时，看 Container Station 里 `taihaoshuo-updater` 在不在运行、它的日志里有没有拉取镜像出错（比如 ghcr.io 的登录令牌过期）。
- **书架上的书都标成“文件找不到”**：一般是共享文件夹改了名或者没挂上。把 compose 里 `volumes` 的路径改对、“更新”应用程序，再在“设置 → 书库目录”里点“扫描”，文件找回来就会自动恢复（30 天内都可以）。
- **NAS 空间不够**：“设置 → 存储与状态”里清理缓存、调小缓存上限；“设置 → 回收站”里清空回收站。
- **打不开网页**：确认容器在运行、端口 27200 没被别的程序占用（见上面“网络”）；手机上看看是不是连到了别的 Wi-Fi，或者 Tailscale 没开。

## 安卓 App

用 WebView 直接打开 NAS 上的书库网页，界面和网页端一样、跟着书库一起更新；手机自己负责网络、离线、后台听书这些网页做不到的事。

**安装**：在仓库的 Releases 里下载 `shuku-android.apk`（或者手机浏览器打开书库网页“设置 → 版本与升级”点“下载”），在手机上点开安装（第一次要允许“安装未知应用”）。Android 8.0 及以上。以后有新版本，App 会自己提示更新（见[在线升级](#在线升级)）。

**连接**：

1. 电脑打开书库网页 →“设置 → 手机、手表和浏览器插件”→“显示配对二维码”。
2. 用手机相机扫二维码，会直接打开书库 App 并连好；或者打开 App 填书库地址和配对码。也可以改用访问密码登录。
3. 内网地址和 Tailscale 地址填一个就行，连上后 App 会自动在两者之间切换。

**功能**：

- **离线**：书的详情里点“下载到手机”，没网时书架只显示下载过的书，照样能读、能记进度，联网后自动同步进度。“设置 → 手机 App”可以打开“自动下载在读的书”（只在连着内网时下载）。界面文件也缓存在手机上，断网打开不会白屏。
- **后台听书**：锁屏、切到别的 App 也会继续朗读；通知栏、锁屏、蓝牙耳机按键都能暂停和切句；拔耳机自动暂停；来电时暂停。声音可以选书库的微软自然语音，或者手机自带的语音（不联网也能用）。Wear OS 手表上会自动出现播放控制。
- **阅读**：音量键翻页（听书时音量键还是调音量）、阅读时屏幕常亮、状态栏颜色跟着阅读主题，返回键先关面板再退出阅读器。
- **加入书库**：在文件管理器、浏览器下载、微信等 App 里把电子书“分享”给书库，或者用书库“打开”，就会上传到书库自动入库。分享的是下载链接（比如在手机浏览器里长按链接 → 分享）时，书库会在 NAS 上直接下载。
- **手表**：“设置 → 手机 App → 连接手表”把连接信息发给手表。

需要的权限：网络、通知（显示听书控制和上传进度）、前台服务（后台听书）。

### 墨水屏阅读器（墨案 inkPad、文石 BOOX 等）

装同一个 `shuku-android.apk` 就行（32 位、64 位的设备都能装）。

- **墨水屏模式**：App 认出是墨水屏阅读器（品牌、型号，墨案固件号里的“EPD”）时自动打开，也可以在“设置 → 外观”里手动开关。纯黑白显示，没有动画、阴影和半透明（墨水屏上会留残影、发虚），选中的地方反白；阅读时白底纯黑字、一律按页翻（PDF 也是）、没有翻页动画，翻页键（PAGE UP / PAGE DOWN）和音量键都能翻页；阅读设置里不显示亮度、暖色滤镜。
- **字号按屏幕尺寸**：App 把屏幕的实际尺寸告诉网页，界面字号自动放大一些（“设置 → 外观 → 界面字号”能自己调，所有设备都能用）；阅读的默认字号按屏幕算成大约 3.8 毫米高，自己调过的照样记住。
- **排版**：10 寸的（比如墨案 inkPad X）用电脑那种带侧栏的排版，6、7 寸的用手机那种；竖着拿一页一栏，横过来两栏。墨水屏上不用左右滑：“继续阅读”排成两行格子，入口、筛选折行显示。
- **大书也打得开**：在线时不先下载整本书，只取正在看的那一章（书库在 NAS 上解压、压缩传输，后面两章预先取好）；一章几百 KB、几 MB 的大章节由书库拆成小段，比屏幕大的插图缩到屏幕大小再传；在书里搜索用书库的全文索引。断网时（App 里下载到手机的书）照旧整本打开。
- **PDF 由书库画**：在线时 PDF 的每一页由书库画成和屏幕一样宽的 16 级灰度图片，文字另外取来铺一层看不见的文字（选字、查字典、划线、听书、翻译照旧），目录也由书库读；不用整本下载，几千页的也几秒打开，旧网页组件画字体丢字的问题也没有了。漫画一律按屏幕宽度缩小再传。
- **旧系统也能打开**：这类设备的系统自带网页组件（Android System WebView）往往很旧，新写法的网页跑不起来（打开是一片白）。书库会自动给旧浏览器换一套降级过的网页（功能一样，`tools/legacy` 构建，打包时一起放进镜像），App 也会把这一套预先缓存，离线也能打开。
- 万一还是打不开，屏幕上会显示网页组件的版本和出错原因（不再是一片白），拍下来就能知道是哪里不兼容。

## Wear OS 手表

**安装**：手表 App 没上架应用商店，要用电脑的 adb 装（Wear OS 3 及以上）。adb 在 Google 的 [SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools) 里，下载 Windows 版解压就能用：

1. 手表上：设置 → 系统 → 关于 → 连点“版本号”7 次打开开发者选项；开发者选项里打开“ADB 调试”和“无线调试”。
2. 电脑和手表连同一个 Wi-Fi。在无线调试里点“配对新设备”，电脑上执行 `adb pair 手表IP:配对端口`，输入配对码；再执行 `adb connect 手表IP:端口`。
3. `adb install shuku-wear.apk`

手表 App 和手机 App 的包名、签名必须一样（同一次打包出来的就是一样的），手表才能和手机通信。

也可以用手机上的 Wear OS 工具箱装：在手机书库 App 的“设置 → 版本与升级”点“更新手表”，安装包会存到手机的“下载”文件夹并交给工具箱。以后升级也是这样（见[在线升级](#在线升级)）。

**连接**：手机上打开书库 App →“设置 → 连接手表”；或者在手表上点“从手机获取”。手机不在身边时，也可以在手表上“手动输入地址”，填书库地址和配对码。

**功能**：

- “在读”列表，点开就在手表上读：按章节显示，表冠滚动，可以调字号、跳目录；读到哪里同步回书库，手机和网页接着读。
- **在手表上听书**：打开一本书，点章节开头的“听书”，或者点一下正文再点“从这里听”，手表自己朗读（书库的微软自然语音，和手机听书同一个音色；书库语音用不了时改用手表自带语音）。播放页能上一句、下一句、暂停、调语速、定时（15/30/60 分钟、读完本章）；读完一章接着读下一章，熄屏也继续；进度传回书库。Wear OS 建议用蓝牙耳机听：没连耳机时会提示去连，手表有扬声器的话也可以选用扬声器。耳机断开自动暂停。手机正在朗读时，在手表上开始听会先让手机停下。
- 首页显示手表、手机上正在朗读的书，可以暂停、继续、上一句、下一句。
- “找书”：搜索书名、作者（可以用手表的语音输入），或者看最近加入的书。
- 打开过的那一章和下一章存在手表上，路上没网也能接着读；没网时记下的进度，联网后补传（期间在别处读过的话保留那边的位置）。
- 漫画、扫描版 PDF 没有文字，手表上不能读。
- **Tile**：在表盘上左右滑能看到书库的 Tile——今天读了多久、在读的书，点“继续读”“继续听”。没看到的话：长按表盘往左滑到底，点“+”添加“书库”（不同品牌的手表叫法略有不同）。
- **表盘复杂功能**：长按表盘 →“编辑”/“自定义”→ 选一个复杂功能的位置 → 选“书库 · 今天读书”，表盘上就显示今天读了几分钟，点一下接着听。
- **离线听书**：开始听时会把后面 4 章的正文存到手表上，播放时提前准备约 4 分钟的语音；出门前在播放页点“多准备一些”，能准备约 30 分钟（最多 60MB，听完、换书时自动删掉）。路上没网时先放准备好的，再用手表自带的语音接着读。
- **省电**：手表只在你用的时候联网；Tile 和复杂功能最多半小时刷新一次；听书暂停 10 分钟后自动关闭。在手表上听书本身要一直联网和播放，耗电会比较多，长时间听建议用手机。

手表通过手机的蓝牙或自己的 Wi-Fi 上网。在外面用 Tailscale 时，手表经手机转发的流量能不能走 Tailscale 取决于手机系统，连不上时只能在家里用手表读（控制手机听书不受影响；在手表上听书时连不上书库，会用手表自带语音读已经存在手表上的章节）。

## 浏览器插件（Chrome / Edge）

在任何网站上，点一下工具栏里的书库图标，就列出这个页面上所有的电子书链接（EPUB、MOBI、AZW3、FB2、PDF、DJVU、漫画包等，包括页面里的框架），同一本书的几种格式合成一组、默认选最合适的格式，勾选后一次加入书库。也可以在下载链接上点右键 →“添加到书库”。

**安装**：解压打包出来的 `shuku-extension.zip`（或者直接用源码里的 `extension` 文件夹）→ Chrome 打开 `chrome://extensions`（Edge 打开 `edge://extensions`）→ 打开“开发者模式”→“加载已解压的扩展程序”→ 选这个文件夹。

**连接**：装好后会自动打开插件设置，填书库地址和配对码（网页“设置 → 手机、手表和浏览器插件 → 显示配对二维码”）。插件和手机一样自动在内网和 Tailscale 之间切换。

**更新**：插件发现新版本时图标上显示“新”，按弹窗里的提示下载、覆盖原来的文件夹、重新加载（见[在线升级](#在线升级)）。

**加入方式**（插件设置里选）：

- **自动**（默认）：古腾堡计划、Standard Ebooks、互联网档案馆、维基文库这些公开书库交给书库直接下载；其他网站用浏览器下载后传到书库，能带上你在那个网站的登录状态和来源页。50MB 以上的文件，如果不登录也能下载，就直接交给书库下载（不用先经过电脑）。书库下载失败时自动改用浏览器再试一次。
- **都用浏览器下载后上传**：适合 NAS 上不了外网的情况，单个文件最大 1GB。
- **都让书库下载**：不占电脑的网络，浏览器关了也会继续。

在古腾堡计划、Standard Ebooks、互联网档案馆、维基文库的书页上，插件会把各种格式合成一本，互联网档案馆还能“整本加入”（书库自动挑 EPUB 或 PDF），维基文库会生成整部作品的 EPUB。下载到的其实是网页（比如要先登录）时会说明原因，可以换一种方式重试。

大文件在插件的后台页面里下载和上传，弹窗关掉也会继续，显示百分比；上传中断会换另一种方式再试。书库那边的下载任务 30 分钟没有进展、或者 30 分钟连不上书库，插件会停止等待并说明原因。

往书库里加书只有管理员能做：插件要用管理员的账号配对（家人账号配对的插件会提示）。

插件只在你打开弹窗或使用右键菜单时读取当前页面上的链接，下载的文件只发到你自己的书库。请只添加你有权下载的内容。

## Windows 桌面版（听书加速器）

“设置 → 手机、手表和浏览器插件”里点“下载书库桌面版”（书库现场打包，带着书库地址），解压到一个固定的文件夹，双击“启动书库.cmd”。右下角托盘出现书库图标，浏览器打开桌面版的设置页（`http://127.0.0.1:27230`，只有这台电脑能打开），填配对码。

- 托盘菜单：打开书库、设置和状态、帮书库加速（开 / 关）、开机自动启动、检查更新、退出。
- 加速：书库的微软语音不行时，听书包要合成的句子交给电脑（MeloTTS 中英，和 NAS 本地语音同一个模型，第一次从书库下载约 170MB），合成好传回书库。电脑只往外连书库拉活、交活，不用开端口。电脑空闲时全速，最近一分钟用过键盘鼠标时降到一半左右，用电池时不干活（可以改），程序优先级比别的程序低。
- 数据在 `%LOCALAPPDATA%\Shuku`（设置、日志、模型）。每 6 小时检查一次更新，有新版自己换上程序。

## 打包（GitHub Actions）

NAS 服务器镜像、安卓 App、手表 App 和浏览器插件都用 GitHub Actions 打包，**只在手动运行时才打包**，不会因为推送代码自动运行：

1. GitHub 仓库页面 → Actions →“打包 App 和插件”→ Run workflow。可以填版本号（只用数字和点，最多三段，比如 `1.0.1`），留空就用 `android/gradle.properties` 里的；后面会自动接上第几次打包，比如 `1.0.1.12`。
2. 每次都把服务器、手机 App、手表 App、插件一起打包（各端的安装包要放进服务器镜像，在线升级才能拿到），大约 6～8 分钟。运行环境分两层做成镜像，没变就一直用：`ghcr.io/smallyjh-boop/shuku-base`（Debian、Calibre 等，只在 Dockerfile 里 `base` 那一段改了、或者勾了“重新制作基础镜像”时重做，多 3 分钟左右，NAS 要多下载几百 MB）；`ghcr.io/smallyjh-boop/shuku-runtime`（再加上本地字典，只在字典数据、转换程序改了或者勾了“重新生成本地字典”时重做，多 1 分钟左右，NAS 要多下载几十 MB）。镜像推到 `ghcr.io/smallyjh-boop/shuku`，NAS 一分钟内自动升级；安装文件另外发在仓库的 Releases 里（文件见上面“部署到威联通”的表格），另有校验值 `SHA256SUMS.txt`。

为了省 Actions 的分钟数和存储额度：整个打包只有一个任务；手机和手表在同一次 Gradle 里并行打包；服务器只打 x86 版（NAS 是 Intel 处理器），不用模拟器；不建缓存、不上传 Artifacts（Release 附件不占存储额度），ghcr.io 上只留最近 10 个版本（可以退回），超过 35 分钟自动停止。服务器先跑自动测试（数据库升级、家人账号、回收站、扫描、备份恢复等）；构建兼容旧系统的网页（Node，几秒钟）；镜像再试运行，接口、网页、各端安装包的下载、转换工具、Calibre 转换和本地字典都正常，并且用上一版建的数据库升级后书、进度、笔记、登录都还在，才推送和发布。每次运行的内部版本号自动加一，新的 APK 可以直接覆盖安装。

签名：默认用仓库里的 `android/signing/shuku.jks`（密码 `shuku-app`），自己用没问题。如果要公开分发，请换成自己的签名：在仓库 Settings → Secrets and variables → Actions 添加 `SHUKU_KEYSTORE_BASE64`（签名文件 `base64 -w0` 后的内容）、`SHUKU_KEYSTORE_PASSWORD`、`SHUKU_KEY_ALIAS`、`SHUKU_KEY_PASSWORD`。换签名后手机和手表都要卸载重装。

也可以在自己电脑上用 Android Studio 打开 `android` 文件夹，或者执行 `cd android && ./gradlew :app:assembleRelease :wear:assembleRelease`（需要 JDK 17 和 Android SDK 35）。

## 命名规则

默认：

- 图书：`{分类}/{作者}/{书名}{ (年份)}/{书名} - {作者}` → `小说/刘慈欣/球状闪电 (2005)/球状闪电 - 刘慈欣.epub`


本地开发：

```sh
cd server && go build -mod=vendor -tags sqlite_fts5 -o shuku . && go test -mod=vendor -tags sqlite_fts5 ./...
SHUKU_DATA=./data SHUKU_INBOX=./inbox SHUKU_WEB=../web SHUKU_LIBRARIES="图书:$PWD/books:book,漫画:$PWD/comics:comic" ./shuku
```

`tools/run-test.sh` 会生成一批文件名很乱的测试书（GBK 的 TXT、带内嵌信息的 EPUB、Word 导出的 PDF、漫画、重复文件、写法不同的作者文件夹），启动服务器并自动入库。

`python3 tools/e2e.py` 把所有功能自动走一遍：启动服务器和模拟的联网服务（豆瓣、Open Library、语音、AI、OPDS、维基文库、互联网档案馆），从接口、网页（电脑、手机尺寸、深色、模拟安卓 App 的原生桥）、浏览器插件（无头 Chromium 里装上插件）三方面检查，截图在 `/tmp/shuku-e2e/shots`。`--api` 只查接口，`--api --ext` 只查接口和插件。需要 Go、Python 的 requests / Pillow / reportlab / playwright。

`android/tools/check.sh` 不需要 Android SDK：用 Kotlin 编译器加 `android.jar` 检查手机和手表两个 App 的代码能否编译，再检查清单和资源引用。

## 关于微软自然语音

微软的朗读接口需要一个每 5 分钟变化的校验值（`Sec-MS-GEC`），书库按开源项目 edge-tts 的算法生成（第二版格式），并带上和 Edge 浏览器一样的版本号。微软改了接口导致试听失败时：

- 先在“设置 → 听书”里试听，看出错信息；可以用环境变量 `SHUKU_EDGE_VERSION` 换成新的 Edge 版本号试试。
- 备用办法：在 NAS 上用 Docker 跑一个 [openai-edge-tts](https://github.com/travisvn/openai-edge-tts)（它会跟进微软的变化），书库“设置 → 听书”的声音来源选“自定义语音接口（OpenAI 兼容）”，地址填 `http://NAS的IP:5050/v1`，API Key 填 openai-edge-tts 里设置的 `API_KEY`，音色填 `zh-CN-XiaoxiaoNeural` 这样的名字。声音还是同一套微软自然语音。
